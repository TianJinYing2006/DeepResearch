# 域名切换手册（ikaoju.cn）

> **定位**：把公网入口从「IP 直访 + 自签证书」切到正式域名 `ikaoju.cn` 的**唯一操作口径**。
> 部署形态见 `deployment.md`，发布流程见 `release-runbook.md`，上线准入见 `production-readiness.md`。
>
> **安全口径**：本文件进入公开仓库。域名 `ikaoju.cn` 为公开信息可写；
> **服务器公网 IP、密钥、口令一律用占位符**，不得落库。
>
> 建立：**2026-10-08**（主理人购入 `ikaoju.cn`，服务器为大陆云、已在跑 IP 直访）。

## 1. 结论先行：现在能不能切

**不能。** 原因不是技术问题，是行政前置条件未满足。

| 事实 | 值 |
|---|---|
| 域名 | `ikaoju.cn`（`.cn` 国别域名，刚购入，**未备案**） |
| 服务器 | **腾讯云，已购一年**（境内节点）⇒ 备案资格 ✅ 满足 |
| 当前入口 | `DR_DOMAIN=https://<公网IP>` + Caddy 内部 CA 自签证书，**可用** |
| 拦截后果 | 未备案域名解析到大陆 IP ⇒ **80 被 webblock 拦截、443 按 SNI reset** |

⚠️ **最坏操作**：现在把 `DR_DOMAIN` 改成 `ikaoju.cn` 并重启 Caddy。
结果是**新域名不通**（拦截，Let's Encrypt 的 HTTP-01 挑战走不完，证书签不出来），
**同时旧的 IP 直访入口被你自己改掉** ⇒ 内测直接断供。**这段时间内不要动 `.env` 的 `DR_DOMAIN`。**

技术侧其实只差 6 个环境变量（§4），真正的时间成本在备案：**10~30 个工作日**。

（轻量国内节点要求 ≥3 个月，一年绰绰有余）。下面 3 项提交前自查，任一不满足会被退回。

| # | 检查项 | 判据 | 状态 |
|---|---|---|---|
| 1 | **服务器备案资格** | 腾讯云轻量 / CVM 国内节点，购买时长 ≥ 3 个月；**境外节点不支持备案** | ✅ **已确认通过**（一年期） |
| 2 | **域名实名认证** | 已完成实名，且**实名满 3 个自然日**（未满直接驳回） | ⬜ 待确认 |
| 3 | **三方姓名一致** | 身份证姓名 ≡ **域名持有者** ≡ **腾讯云账号实名认证名称**，逐字一致 | ⬜ 待确认 |

> ⚠️ 第 3 项是三处对齐，不是两处。腾讯云官方口径明确要求主办者姓名
> 「需与个人证件上的名称以及账号实名认证名称一致」。账号没实名或实名不符，先去改账号认证。

**域名侧（已确认 `ikaoju.cn` 在腾讯云注册）**：

- ✅ **免传域名证书**（腾讯云注册域名在腾讯云备案不需要域名证书）。
- ⚠️ 但仍需**域名实名认证截图**（含域名 / 所有者 / 证件类型 / 证件号 / 过期时间）。
- 🚨 **域名注册后必须先实名认证**，否则域名处于 **ServerHold（暂停解析）** 状态，解析都用不了。

### 2.1 🚨 今天提交不了：域名实名的时间账

腾讯云官方口径（文档 216/60959、FAQ 243/19629）：

> 腾讯云注册的域名通过实名认证后需要**满 3 个自然日**才能提交备案
> （非腾讯云注册的域名需满 3 个工作日）。
> 原因：实名通过后，腾讯云要把实名数据**上传工信部**，此过程工信部还查不到实名信息。

腾讯云购买页的实际提示是「等待上报实名信息，**平均 3~5 个工作日**」；
实名审核本身「一般 1 个工作日内完成，部分需 3~7 个工作日」。

| 时间 | 动作 |
|---|---|
| T+0（今天） | **去完成域名实名认证**——这是今天唯一能做的实质推进动作 |
| T+1~7 | 实名审核通过 |
| T+3~5（自实名通过起） | 工信部可查到实名信息，备案系统才允许提交 |
| 之后 | 才能点「开始备案」 |

⇒ **别在实名未满期时硬提交**，系统会提示「该域名没有进行实名认证」，白白生成一个流程中的订单
（而一个账号同时只能有 1 个流程中订单，卡住反而要等它驳回或撤销）。

**提交入口**：必须是**服务器所在云厂商**的备案系统，不能自己向管局提交。
腾讯云 `cloud.tencent.com/product/ba`；阿里云 `beian.aliyun.com`；华为云各自入口。
域名在哪买的**不影响**——备案跟服务器走，非本平台注册的域名也能在该平台提交。

## 3. 备案流程与材料

### 3.0 今天就能做的三件事（实名等待期不浪费）

备案订单还提交不了，但这三件现在就能推进：

| # | 动作 | 入口 |
|---|---|---|
| 1 | **完成域名实名认证**（最优先，它决定后面所有时间） | 腾讯云控制台 → 域名注册 → 我的域名 → `ikaoju.cn` → 实名认证 |
| 2 | **核对腾讯云账号实名认证姓名** ≡ 身份证姓名 ≡ 域名持有者 | 控制台 → 账号中心 → 实名认证 |
| 3 | **准备材料**：身份证正反面原件照、可接通的手机号、邮箱 | 手机拍好备用，别用翻拍的屏幕照 |

### 3.1 时间线

| 阶段 | 耗时 | 关键动作 |
|---|---|---|
| **域名实名 + 上报工信部** | **3~5 个工作日**（前置，见 §2.1） | ⚠️ 未完成则无法提交备案订单 |
| 填写信息 + 上传材料 | 当天 | 主体信息 / 网站信息 / 视频核身 |
| 腾讯云初审 | 1~2 工作日 | 材料齐全性、信息一致性、网站名称合规 |
| **工信部短信核验** | **24 小时内必须完成** | ⚠️ 超时自动驳回，全流程重来 |
| 管局终审 | 5~20 工作日 | 各省差异大；广东 / 北京 / 上海偏慢 |
| 公安联网备案 | ICP 后 **30 日内** | `beian.mps.gov.cn`，1~3 工作日 |

### 3.2 腾讯云备案五步（首次备案）

入口：腾讯云控制台 → **ICP 备案** → 我的备案 → 开始备案（也可微信小程序扫码进入）。

| 步骤 | 填什么 |
|---|---|
| ① 验证备案类型 | 备案地区 / 备案性质=**个人** / 证件类型 / 主办者姓名 / 域名 / 云资源（选你那台一年期服务器） |
| ② 主体信息 | 证件住址、通信地址（**精确到门牌号**）、手机号（**须与账号绑定手机号一致**）、邮箱 |
| ③ 网站信息 | 服务名称、域名、服务内容、服务语言 |
| ④ 补充材料 | **域名实名认证截图**（腾讯云域名**免传域名证书**） |
| ⑤ 提交 + 视频核身 | 微信扫码做人脸视频核身 |

**只备案 `ikaoju.cn` 一个域名就够了。** 腾讯云口径：**个人备案每个订单最多 1 个网站，
每个网站只能包含 1 个域名**；`www.ikaoju.cn` 是二级域名，主域名备案成功后可直接解析使用，
不占用这个名额，也不必单独备案。

**服务名称（网站）建议**：个性化名称，避开「中国 / 中华 / 国家」等字样，
不要带企业性质词汇。例如「于晏的技术研究笔记」这类。

## 4. 切换操作（备案通过后执行）

### 4.1 DNS 解析

在域名解析控制台加记录（**等备案号下来再加**，提前加会被拦）：

| 类型 | 主机记录 | 记录值 | TTL |
|---|---|---|---|
| A | `@` | `<公网IP>` | 600 |
| A | `www` | `<公网IP>` | 600 |

验证：`nslookup ikaoju.cn` 返回的 IP 与服务器公网 IP 一致。
（DNS 最长 72 小时生效，实际通常数小时。**切换前先把 TTL 调到 300** 加快生效。）

### 4.2 服务器 `.env` 改动（6 项）

```bash
cd /opt/deepresearch

# 1) 切域名（注意：域名模式不要带 https:// 前缀，Caddy 自动 HTTPS）
sed -i 's|^DR_DOMAIN=.*|DR_DOMAIN=ikaoju.cn|' .env

# 2) 清空 IP 直访的 SNI 回退（域名模式不需要）
sed -i 's|^DR_DEFAULT_SNI=.*|DR_DEFAULT_SNI=|' .env

# 3) CORS：必须是完整 origin，带协议不带路径
sed -i 's|^DR_CORS_ORIGINS=.*|DR_CORS_ORIGINS=https://ikaoju.cn|' .env

# 4) 邮件链接基准（密码重置 / 分享链接都用它）—— 域名不对则外发链接全废
sed -i 's|^DR_MAIL_BASE_URL=.*|DR_MAIL_BASE_URL=https://ikaoju.cn|' .env

# 5) 错误追踪域名（仅 --profile errors 启用时需要）
sed -i 's|^DR_GLITCHTIP_DOMAIN=.*|DR_GLITCHTIP_DOMAIN=https://ikaoju.cn|' .env

# 6) 反代可信 CIDR（若之前未配）—— Docker 网桥段，别再用 DR_TRUST_PROXY=true
# DR_TRUSTED_PROXY_CIDRS=172.16.0.0/12
```

> ⚠️ `Caddyfile` **不用改**，已用 `{$DR_DOMAIN}` 参数化，SSE 穿透配置（不压缩 + `flush_interval -1` + 3900s 超时）已就绪。

### 4.3 防火墙与重启

```bash
# 放行 TCP 80 / 443（腾讯云轻量：控制台 → 实例 → 防火墙）
# 注意：备案前这两个端口对未备案域名是拦的，备案通过后自动放行

docker compose -f docker-compose.staging.yml --profile proxy up -d
# bind mount 的 Caddyfile 不会因 .env 变化触发重建，必须显式重启 caddy
docker compose -f docker-compose.staging.yml restart caddy

docker compose -f docker-compose.staging.yml logs -f caddy   # 看 ACME 签发过程
docker ps --format 'table {{.Names}}\t{{.Status}}' | grep caddy  # 应为 (healthy)
```

### 4.4 冒烟（逐条，缺一不可）

```bash
curl -fsS https://ikaoju.cn/api/health/ready          # 应返回 ready
curl -fsS -o /dev/null -w '%{http_code}\n' https://ikaoju.cn/   # 200
curl -fsS https://ikaoju.cn/api/options               # 前端配置下发
curl -fsS https://ikaoju.cn/api/legal/privacy         # 镜像内 docs/legal 可读
```

**必做**：浏览器跑完一个完整任务，确认**进度条持续推进不中断**（SSE 穿透验收，
`production-readiness.md` §7.1 明确要求真机验证一次）。
外加验证登录 / 注册、密码重置邮件里的链接域名正确。

### 4.5 回退

改回 `DR_DOMAIN=https://<公网IP>` + `DR_DEFAULT_SNI=<公网IP>` 并 `restart caddy` 即可，
**回退代价 = 自签证书警告**，不影响数据。数据库与卷全程不动。

## 6. 等待备案期间，值得先做的事

切换本身只有 10 分钟，等待期有 10~30 个工作日。按优先级：

| 优先级 | 事项 | 说明 |
|---|---|---|
| **P0** | **把数据库备份装上 cron + 做一次真实恢复演练** | `deployment.md` §6.1 的 P0 缺口：服务器只有代码包备份、**无 `pg_dump`**。当前已有真实内测数据。**这比换域名重要得多** |

| P1 | 补构建版本锚点 `BUILD_INFO` | `deployment.md` §6.2：服务器非 git 仓库，无法回答「跑的是哪个 commit」 |
| P2 | 固定 `qdrant/qdrant:latest` 的具体 tag | 其余服务均已钉版本，仅 qdrant 未钉 |

### 6.1 P0 备份：脚本已有，只差部署

✅ **脚本已存在于仓库**：`tools/backup.sh`（`pg_dump -Fc` + **`pg_restore -l` 可读性校验**，
校验不过不算备份成功；保留 14 份）+ `tools/backup-cron.sh`（每日 + 非对称加密 + rclone 同步 COS）。
⇒ **不是要写脚本，是服务器上没配 cron。**

**A. 最小可用（今天就能配，5 行）** —— 本地明文 dump，够挡住「卷误删 / 迁移事故」：

```bash
# 服务器 root，先手动跑一次确认能出文件
docker compose -f /opt/deepresearch/docker-compose.staging.yml exec -T postgres \
  pg_dump -Fc -U deepresearch deepresearch > /opt/deepresearch/backups/pg_test.dump
pg_restore -l /opt/deepresearch/backups/pg_test.dump | head   # 能列出目录才算成功

# 装 cron（每天 03:00）
(crontab -l 2>/dev/null; echo '0 3 * * * docker compose -f /opt/deepresearch/docker-compose.staging.yml exec -T postgres pg_dump -Fc -U deepresearch deepresearch > /opt/deepresearch/backups/pg_$(date +\%Y\%m\%d_\%H\%M\%S).dump') | crontab -
```

**B. 完整版（推荐）** —— 走 `tools/backup-cron.sh`，带加密与异地：
先生成密钥对，**私钥离线保管、服务器只放公钥证书**；再配 rclone 的 COS remote；
最后 `30 3 * * * /opt/deepresearch/tools/backup-cron.sh >> /var/log/dr-backup.log 2>&1`。
前提：证书 `/opt/deepresearch/backup-recipient.crt` 存在（缺失时脚本直接 exit 1）。

⚠️ **两种都得做恢复演练**：`pg_restore -l` 能列出 ≠ 云上能恢复。
CI 里跑的是 CI 环境，**不代表你的服务器能恢复**。备份配完当天必须真恢复一次。

**不要做的事**：不要在备案期间改 `DR_DOMAIN`、不要提前把域名解析到服务器。
