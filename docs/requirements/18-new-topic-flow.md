## 2. 问题背景

R6b-2「报告优先版式」在报告完成后自动折叠启动表单（`App.tsx` `useEffect(result ⇒ setLaunchOpen(false))`）。
用户要开下一话题需：展开折叠条 → 手动清空上一轮 topic → 再输入。移动端路径更长。

## 3. 需求分析

终局态（成功 / 失败 / 取消）后，「开新话题」**≤1 次点击直达**，且表单为干净状态：
主题/附加要求清空、**档位保留**、输入框聚焦；不刷新页面即可直接提交第二单。

## 4. 当前设计（代码位置）

- `App.tsx`：`launchOpen` 状态 + `result ⇒ 自动折叠`；表单状态 `topic/instructions/profile`；
  R3 草稿（`sessionStorage dr.draft`）与 P1-7 重试（`lastRequest`）各自独立；
- `features/launch/LaunchPanels.tsx` 折叠态：摘要条（topic + 档位）+ 单个「修改参数」按钮（`launch-expand`）；
- 现状缺口：无「新研究」主动作；清空需手动。

## 5. 优化方案（业内口径）

行业调研（ChatGPT / Claude.ai / AI chat UX 指南）：
- "New chat" 是**常驻且一等**的入口（侧栏顶/头部），不藏在折叠层里；点击即回到干净起点；
- **焦点管理**：仅在用户**显式**动作后聚焦输入框（「回复完成时不抢焦点」是明确反模式）——
  与本项目现状一致，本次只在点击「新研究」后聚焦；
- 重置语义 = 清空会话输入，保留用户级偏好（模型/档位类比"model picker"不重置）。

落地（最小改动、纯前端）：
1. 折叠摘要条增加 `新研究` 主按钮（`data-testid="launch-new-topic"`），与「修改参数」并列；
   运行中 `disabled`（避免清空正在跑的输入）；
2. `App.handleNewTopic()`：清空 `topic/instructions`、`setExportState('idle')`、展开表单、
   写 live region 播报、`focus()` 到 `#topic`；**`profile` 不重置**；
3. 草稿语义：点击「新研究」后清空会经 R3 草稿链路落库（sessionStorage），刷新不回带已结束话题；
   未点击时保留表单内容（便于「改参复跑」——与 P1-7 重试互补），**不主动清空**；
4. 移动端：折叠条本身在单列流内，按钮同样一屏可达。

## 6. 设计策略

- 纯前端改动，不动后端 API / SSE 协议 / D-19 前台模型；
- 复用现有布局（折叠条即报告旁的常驻区域），不新增全局导航；
- 可访问性：按钮键盘可达；动作结果写 `live-region`（沿用 R1 审计通道）。

## 7. 验收标准（DoD）

- [x] 终局态折叠条有「新研究」按钮（桌面 + 移动；运行中禁用）
- [x] 点击后：主题/附加要求清空、档位保留、`#topic` 聚焦；无需手动清理/滚动
- [x] 未提交草稿行为不回退（R3 用例回归；本次不清空未点击时的表单）
- [x] E2E 新增：完成一单 → 点新研究 → 不刷新页面直接提交第二单
- [ ] CI 全量（lint-and-test + infra + frontend + e2e）零回归

## 8. 影响范围与风险

- 模块：`web/frontend/src/App.tsx`、`features/launch/LaunchPanels.tsx`、`e2e/research.spec.ts`；

- 兜底：清空前的内容已随 run 落库（历史可回看），不存在数据丢失。
