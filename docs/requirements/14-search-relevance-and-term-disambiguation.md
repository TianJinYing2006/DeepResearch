## 2. 问题背景

内测实测（run `588cb42e6fb7`，主题「JEV对企业项目落地的影响」）：

- 搜索源（博查）对「JEV」做拼写纠错 / 联想，返回 EVA（经济增加值）语料；
- 管线照常产出：12 个来源 / 30 条 findings / 引用校验 **7/7 严格通过（存在性 AND 忠实度）**；
- 报告自身如实标注「EVA 与 JEV 存在混淆或相似性……无法得出可靠结论」——**没有编造**，但**偏题来源未在检索层被识别**。

结论：这不是引用校验漏洞，而是两个层次的职责分工——「引用保真（存在 + 忠实）」
**不承诺**「主题相关」；当前管线在**检索 / 规划层没有术语消歧与来源相关性闸**。

## 3. 需求分析

目标：降低「缩写 / 术语混淆（JEV↔EVA 类）」引发的偏题来源进入 findings 与报告的概率。

可量化成功定义（基线待测）：

- 构造「术语歧义评测集」（≥10 题，覆盖：同形缩写跨领域、一词多义、中英混写）；
- 指标：主题术语在来源标题 / 片段中的命中率、人工抽检偏题来源比例、报告偏题警示触发率；
- 以**同题同源**口径可复算（不依赖随机重采样，避免 W8 统计不可判定的教训）。

## 4. 当前设计（代码位置）

- 规划与编排：`research_engine/graph.py`（6 节点 + critic 回环）、`research_engine/agents/researcher.py`（多跳检索，工具层并行）；
- 搜索源：`research_engine/search/bocha.py`（默认源）；检索结果无相关性过滤 / 术语消歧环节；
- findings 提取：无「主题术语一致性」检查；
- 引用校验：`research_engine/agents/validator.py`（存在性 AND 忠实度；`verified` 口径）；
- 报告可信声明：`research_engine/render.py`（存在性 / 严格忠实 / 宽松三口径）、`graph.py:339` 校验进度文案。

痛点：搜索层纠错行为不可控；规划层未先做「术语确认」；报告层的混淆提示目前是
**模型自发行为**，不是机制保证。

## 5. 优化方案与实施状态

### 5.1 已落地：报告机制化警示（原候选 3，确定性、零 LLM）

- 模块：`research_engine/term_ambiguity.py`
  - 术语抽取：ASCII 词（去停用词）+ 主题 CJK 二元组（去重、保序）；
  - 语料 = findings 内容 + visited_sources（**只判检索层**，不用报告正文自证）；
  - 强信号：主题全大写缩写（如 JEV）在语料 **0 命中** → 告警；
  - 弱信号：整体命中率 < `DR_TERM_HIT_MIN`（默认 0.35）→ 告警；
  - 只影响展示：不改 `run_status`、不写 `degradation_log`（不污染故障归因口径）。
- 渲染：`research_engine/render.py::ReportRenderer.build_term_drift_warning`
  （置顶警示块，与「检索健康告警」同区；`render()` 异常兜底契约不变）。
- 评测集：`research_engine/eval/term_ambiguity_set.jsonl`（10 题：5 缩写混淆 / 2 一词多义 / 2 对照 / 1 混合）。

### 5.2 候补（待基线评测后决策）

1. **术语消歧前置**：planner 首轮生成「术语确认」检索（英文全称 / 领域限定词），
   并检测主题术语在结果中的命中率；命中率过低时改写检索词或显式标注不确定性；
2. **来源相关性标记**：findings 提取前，按术语命中 / 语义相似度对偏题来源降权或隔离
   （复用既有「失败隔离」语义，不改 validator 契约）；
4. **rerank 评估**：是否引入 rerank（当前 `use_rerank=False`）先做对照评测再定
   （参考 W7「rerank 负收益」教训，不做无证据引入）。

> 候补项均涉及提示词 / 检索策略变更，须先跑通 5.1 的评测基线（同题同源）再做 A/B 对照。

## 6. 设计策略

- 不动引用校验口径（引用保真 ≠ 主题相关，两者分层，UI 文案不得混淆）；

- 优先零 / 低新增依赖方案；凡涉及提示词变更，须先评估 W8 基线影响并留痕。
