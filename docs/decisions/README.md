# 设计决策记录（ADR）

本目录记录 DeepResearch 项目的**设计决策**与**修改背景**，作为项目记忆。

## 为什么要有这个目录

- **设计策略有据可依**：每个关键设计决策都记录"背景、方案、理由、取舍"，避免遗忘或重复讨论。
- **修复 bug / 优化设计时记录背景**：任何修改都要先说明"当时为什么这么设计"，再说明"现在为什么改"，形成完整决策链。
- **面试可追溯**：面试官追问"为什么这么设计"时，能讲出完整的决策过程和取舍。

## 规范

1. **每个决策一个文件**，命名 `NNNN-短横线标题.md`，编号递增。
2. **每次修复 bug 或优化设计**，新增一条 ADR，记录：
   - **背景**：当时的设计意图、所处上下文
   - **问题/动机**：为什么现在要改
   - **方案**：做了什么改动
   - **理由与取舍**：为什么选这个方案，放弃了什么
   - **影响**：对哪些模块有影响
3. **模板**见 [TEMPLATE.md](TEMPLATE.md)。
4. 修改代码时，在对应 ADR 中追加"变更记录"，保持决策链完整。
