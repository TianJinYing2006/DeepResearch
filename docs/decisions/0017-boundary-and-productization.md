# ADR-0017：产品边界重划与产品化路线（L3-A/B 内测 → 完整产品）

## 基本信息

- **编号**：0017
- **标题**：产品边界重划：以 L3-A/B 封闭内测为当前边界，在满足五条准入后转为完整产品
- **日期**：2026-10-26
- **状态**：已采纳（主理人 2026-10-26 确认）
- **涉及模块**：全项目治理（`CONTRIBUTING.md` §2、`docs/decisions/`、`docs/project-status.md`、对外表述与发布节奏）
- **关联需求**：`docs/requirements/10-l3-production.md`（L3 需求侧）
- **关联决策**：ADR-0001（初始定位）、ADR-0009（L3 架构，本次转正）、D-19 / D-20（任务模型与技术栈）
- **关联文档**：`CONTRIBUTING.md` v2.1（规则层唯一入口）、`docs/requirements/9-web-ui-rewrite.md`（三条硬边界）

---

## 背景

1. **2026-08-19（ADR-0001）**：项目定位为“不做完整产品（Web UI、用户系统、任务队列等外围功能），聚焦核心研究链路”，以 CLI + 轻量 Web UI 呈现。
2. **2026-09-20（ADR-0001 §1.1 / D-20）**：允许升级呈现层技术栈（FastAPI + React/Vite + SSE），但**不扩展产品边界**，明确“不做登录、用户系统、任务队列、任务持久化、多租户、权限、云端部署”。
3. **2026-09-24（ADR-0009）**：提出 L3 多用户生产化架构（PG 权威状态 + Redis 队列 + 独立 Worker + 用户/配额 + 部署底座），并在文中声明“显式解除 D-19 / D-20 / ADR-0001 §1.1 的 L3 边界”。但该 ADR 一直停留在**草稿（P0 立项）**状态，写着“拍板前不进入实现”。
4. **2026-09-26 至 2026-10-24**：L3 实现已全部落地 —— 27 个迁移、队列 Worker、鉴权（Argon2id/Session/CSRF/MFA/Passkey）、配额与预留式结算、多租户 RAG、内容安全与申诉、报告分享、PDF/DOCX 导出、HITL、MCP 双向、可观测、备份与恢复演练；staging 已公网部署并完成多轮全链路验收。

**结果**：约束文档（ADR-0001 §1.1、D-20 硬边界②）与实现事实直接冲突，且 ADR-0009 的“解除边界”从未获得正式效力。冲突带来三类现实风险：

- 新功能无法判断是否“越界”，只能靠口头共识；
- 对外材料（README、简历、面试材料）与内部约束口径不一致；
- 账号、配额、审核、合规等“产品化模块”被当成临时实验，安全与合规优先级被系统性低估。

2026-10-26 全方位评审确认该矛盾，主理人明确：**可以在需求完善之后转为完整产品**，并要求先把当前阶段边界写清。本 ADR 即该决策的落档。

---

## 问题 / 动机

- 若继续维持 ADR-0001 旧边界：已交付的 L3 全部处于“违规状态”，后续任何维护都缺乏决策依据。
- 若直接宣布“完整产品”：合规（G7 未落档）、质量（coverage 约 40%、约八成小节自认信息不足）、安全（反代信任、MFA 限流、安全头、备份凭据）均未闭环，属于对用户与监管的不诚实承诺。
- 若不写边界：功能继续按惯性扩张，维护面与合规义务只增不减，且对外表述无法收敛。

因此需要一份**分阶段边界 + 明确产品化准入**的决策，既承认 L3 事实，又不把“内测”说成“产品”。

---

## 方案

### 1. 当前阶段：L3-A/B 开放注册内测

**定义**：个人主体、开放注册（邮箱 + 密码）、单机 compose + Caddy 的受控内测；staging 已部署，域名 `ikaoju.cn` 已完成 ICP 备案。

| 维度 | 当前允许 | 当前禁止 |
| --- | --- | --- |
| 主体 | 个人主体（腾讯云账号） | 企业主体对外经营 |
| 用户 | 开放注册（邮箱 + 密码）、配额/预算控制 | 未成年人、批量开户 |
| 商业 | 内部验证、成本核算 | 对外收费、SLA/赔付承诺、发票 |
| 部署 | 单机 compose（PG/Redis/MinIO/API/Worker/Export/Caddy） | K8s、多区域、自动扩缩容、CDN/WAF 以外的复杂基础设施 |
| 数据 | 境内处理；境外服务默认关闭 | 跨境数据传输、境外默认开启 |
| 内容 | 研究、报告、只读分享、导出 | 公开发布平台、UGC 社区、第三方分发 |

### 2. 当前允许的功能面

研究主链路（规划 / 多跳检索 / critic / 写作 / 校验 / 修复 / 渲染）、证据链（快照 / 引文 / 定位 / 分级 / 自检）、RAG 多租户、账号与会话（密码 / TOTP / Passkey）、配额与限流、内容安全与申诉、报告只读分享、导出（md / json / pdf / docx）、HITL（澄清 / 计划审批 / 追问）、MCP 双向（默认关）、可观测（OTel / Prometheus / Sentry）、备份与恢复、管理 CLI。

### 3. 当前禁止 / 延后

- 未经本 ADR 变更记录批准的注册方式变更、对外付费、对外 SLA、对外多租户或开放 API 商业化；
- 移动端 / 桌面客户端、K8s / 多区域 / 自动扩缩容；
- 跨境数据传输、境外服务默认开启；
- 在 G7 合规未落档前进行公开推广、投放或对外收费；
- 任何需要“企业主体”资质的能力（如面向公众的生成式 AI 服务备案）。

> **开放注册内测（2026-10-27 变更）**：允许邮箱开放注册，受注册总开关、每日注册上限、一次性邮箱域名黑名单、配额与月度预算约束；**邮箱验证与 CAPTCHA 未上线、G7 未落档前不得公开推广或投放**。该风险列入转「完整产品」的合规前置（§4 第 2 条）。

### 4. 产品化路线（转“完整产品”的五条准入）

转段必须**同时**满足以下五条，并由主理人书面拍板后新增 ADR：

1. **需求**：目标用户、核心场景、定价/成本模型写成需求文档并冻结；
2. **合规**：ICP 备案、公安联网备案、生成式 AI 相关手续书面确认并落档（G7 完成）；
3. **质量**：固定证据池上的确定性指标达标 + 5~10 人内测判据通过（任务丢失率 0、P0 事故 0、成本与耗时 p50/p90 可接受）；
4. **安全**：P0/P1 安全问题闭环（反代信任、MFA/Passkey 防爆破、安全响应头、备份加密、公开仓脱敏、RLS 兜底评估）；
5. **治理**：本 ADR 的边界条款由新 ADR 修订，`CONTRIBUTING.md` §2 同步更新。

## 理由与取舍

- **为什么承认 L3 而不是回退**：L3 已投入约一个月、27 个迁移、全套集成测试与云上恢复演练，且已有内测数据；回退会销毁真实资产，且与“可审计、可运维”的项目主线相悖。
- **为什么不立即宣布完整产品**：合规 G7 未落档、质量指标未证明、安全 P0/P1 未闭环。现在宣布完整产品，等于把“内部验证”包装成“对公众承诺”，违背项目一贯的诚实口径。
- **为什么用“五条准入”而不是日期**：转段的关键不是时间，而是事实是否成立；用条件约束可以避免“为了发布而发布”。
- **为什么保留 ADR-0001 原文**：ADR 是项目记忆，只追加不删改；被取代的条款通过本文交叉引用，读者能看懂演进链。
- **代价**：产品面扩大带来合规义务（备案、审核、留存、申诉）、维护成本（账号/配额/队列/前端）与对外表述风险；这些代价由 L3 路线本身决定，不是本文引入的。
- **放弃的方案**：① 维持旧边界、把 L3 当临时实验（会导致持续违规与决策真空）；② 立即转完整产品（不诚实、不可持续）；③ 暂不写边界、等自然演进（漂移会继续累积）。

## 影响

- **治理**：`CONTRIBUTING.md` v2.0 生效；ADR 索引补齐；ADR-0009 转正；ADR-0001 变更记录追加“边界条款被取代”说明。

- **安全与合规**：账号、配额、审核、备份、脱敏从“产品化附加项”升级为**必做项**。

- **不改**：`research_engine/` 判定口径、`research_engine/eval/results/` 冻结产物（D-16 / D-18）、CI 硬门禁。
