# ADR-0002：修复 Writer 与 Validator 的引用协议不一致

## 基本信息

- **编号**：0002
- **标题**：修复 Writer 与 Validator 的引用协议不一致
- **日期**：2026-08-19
- **状态**：已采纳
- **涉及模块**：`research_engine/agents/writer.py`、`research_engine/agents/validator.py`、`research_engine/context/manager.py`

## 背景

ADR-0001 设计交叉验证（防幻觉）时，约定 Writer 生成带引用的报告，Validator 做引用存在性校验 + 多源印证。但首次真实端到端测试发现：**Validator 检测到 0 条引用**。

## 问题 / 动机

真实测试（主题"2026年RAG技术的最新进展"）中，Writer 生成的报告质量很高，但**没有使用约定的 `[来源: xxx]` 标注格式**，而是用了 `[15, 16, 17]` 这种数字编号。原因：
1. 研究发现里的 `source` 是完整 URL（网络搜索）或 `rag:xxx`，格式较长，模型不愿意逐条标注
2. 模型更倾向于用数字编号，但数字编号没有和真实来源建立映射

这导致 Validator 无法提取任何引用，**防幻觉主卖点失效**。

## 方案

建立**编号引用协议**：
1. `ContextManager.format_for_writer` 给每个研究发现分配编号 `[N]`，格式为 `[N] 来源: <source> ...`
2. Writer 的 prompt 明确要求用 `[来源: N]` 编号引用（N 是研究发现列表中的编号），并禁止编造编号
3. Validator 新增 `_build_index` 建立"编号 → 真实来源"映射，把 `[来源: N]` 映射回真实来源再做存在性校验

## 理由与取舍

- **为什么用编号而非完整 URL**：完整 URL 太长，模型不愿标注；编号简洁，且能通过映射还原真实来源
- **为什么编号映射放在 Validator**：Validator 是校验方，需要知道编号对应的真实来源才能判断"引用是否真实存在"
- **代价**：编号映射依赖 findings 的顺序，如果 findings 顺序变化，编号含义会变。当前单次研究内顺序稳定，可接受

## 影响

- Writer 现在能正确输出 `[来源: N]` 格式
- Validator 能提取并校验引用（真实测试从 0 条提升到 67 条）
- 存在性通过率仍偏低（17/67），原因是 Writer 用了 `[来源: 5, 72, 77]` 多编号组合，Validator 正则未拆分——见"遗留问题"

## 遗留问题

1. **多编号组合**：Writer 输出 `[来源: 5, 72, 77, 103]`，Validator 正则把整个 `5, 72, 77, 103` 当一个来源，映射失败。需拆分多编号。
2. **编号越界**：部分编号可能超出研究发现实际数量（111 条），或 Writer 编造编号。需校验编号范围。
3. **多源印证率**：supported 率偏低，需优化多源印证逻辑。
