## 9. 后验诊断与归因（2026-09-06，基于 v1.0 raw + v1.1 eval 二次挖掘）

> 工具：tools/posthoc_diag.py（可复跑）。以下结论不在前 8 节常规指标内，是从已落盘 raw 挖出的归因分析——**整个 W5 最有含金量的一节**。

### 诊断 1：planner 不是覆盖度短板
- planner 实际分解 79 个子问题 > 标注期望 67（缺口 -12）。
- **结论：子问题拆解足够，覆盖度低不是"没拆"而是"拆了没查够"**——每条子问题仅 1 条种子查询进 frontier（W4 Q1 拍板），平均 3.85 轮即停。

### 诊断 2：critic 系统性早停（核心发现）
- 19 条 critic_stop 中，**14 条停止时覆盖度 <90%**（早停候选），仅 5 条停得对；hard_stop 1 条。
- **结论：critic 的"充分度"判据显著偏乐观**——它看的是 findings 数量/重复度而非子问题覆盖，直接解释覆盖度 55% 的根因。
- ⚠️ 反思有效性 95% 因此是**结构性虚高**：测的是"停得勤"（是否主动停），不是"停得对不对"（是否充分）。两口径必须分开讲。

### 诊断 3：引用忠实度与覆盖度负相关（反直觉）
- 覆盖度 <60% 组 fidelity 0.757 > 覆盖度 ≥60% 组 0.673。
- 归因：查得多 → findings 主题杂 → writer 对单点忠实度被稀释；查得少 → 只围绕核心写，反而忠实。
- **达标与不达标指标之间存在权衡，不是独立维度**——优化覆盖度可能短期拉低引用忠实度，需联动观测。

### 诊断 4：引用失败主因 = writer 越界发挥（非检索缺失）
- 失败原因 Top：claim 引文越界编码 19 次 / 来源未命中 17 次 / 细节虚构（来源未提）10 次 / 具体实体虚构 7 次 / 概念未提 5 次。
- **结论：writer 在"信息不足"时选择发挥而不是标注"信息不足"**（WRITER_SYSTEM 第 5 条要求标了但未执行）——这是引用准确率 72% 未达标的直接归因。

### 归因链（写给面试）
```
完成率 100%            → 工程闭环稳（硬实力）
覆盖度 55%             → critic 充分度判据偏乐观（诊断 2）
引用忠实度 72%         → writer 越界发挥 / 信息不足不标注（诊断 4）
validator 成本占 47%   → W2 对查最贵，优化方向=降采样/缓存
可执行优化序列：critic 判据加覆盖度信号 → writer prompt 强制"信息不足"标注 → validator 成本优化
```
