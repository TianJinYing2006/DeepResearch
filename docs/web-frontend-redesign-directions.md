## 0. 命题（Design Brief）

| 项 | 内容 |
|---|---|
| 主题 | DeepResearch：**可审计研究**工作台（邀请制内测） |
| 使用者 | 研究员 / 分析师 / 工程师；长时间深读报告、核查引用、管理知识库 |
| 首要任务 | ① 发起研究并观察实时进度；② 阅读并**核验**带引用的报告；③ 回溯历史与知识库 |
| 界面模式 | **Operate**（运行看板，信息密集）+ **Read**（报告长文，可读性优先） |
| 现有视觉 | 深色 `#07100f` + emerald；等宽小字、全大写 eyebrow、圆角卡片套件、渐变与玻璃拟态、4 种强调色并用 |
| 审计结论 | 功能完整、对比度与层级有欠账；视觉不是「坏」，是**默认**（卡片套件 + 模板化 eyebrow + 滥用强调色） |

## 1. 先排除「通用的 AI 默认脸」（skill 明确点名的 cluster）

现有 UI 命中其中数条，必须在选定的方向里被**有意识地替换**，而不是换个颜色继续用：

1. 近黑 + 单一酸性绿强调色（现状 emerald/cyan 气质接近）；
2. SaaS 卡片套件：所有内容切成同款圆角卡、统一阴影、渐变洗底（现状指标卡/结果卡）；
3. 模板化 chrome：每个标题上方一条全大写 tracking 的 eyebrow；「A · B · C」中点串；按钮尾部一律 `→`；
4. 小数据一律等宽字体当装饰。

> 另三种「不要」：米白 #F4F1EA + 衬线 + 陶土色的文艺模板；报纸细线零圆角横排；紫色渐变。

## 2. 三个候选方向

三个方向都保留：深/浅主题下的 **AA 对比**、单一主强调色（状态色只表达状态）、数字 `tabular-nums`、动效仅用于状态变化（≤200ms，`transform/opacity`）。

---

### 方向 A · 任务控制台（Mission Console）｜深色 · 仪器感 · 推荐

**一句话**：像飞行控制台而非「后台模板」——信息靠**规则线与密度**组织，颜色只用来报警和指向。

**色彩令牌**（6 个命名值）

| 名称 | 值 | 用途 |
|---|---|---|
| `console-void` | `#0D100F` | 页面底 |
| `console-panel` | `#131816` | 面板底（与 void 差 4%，不靠阴影分层） |
| `console-hairline` | `#26302C` | 1px 分隔线 / 网格 |
| `console-ink` | `#E7EEE9` | 主文字 |
| `console-muted` | `#9AA8A1` | 次要文字（AA+） |
| `signal-mint` | `#5FE3A1` | 唯一主强调：进行中、当前阶段、主按钮 |
| `signal-amber` / `signal-rose` | `#E8B36A` / `#E4736D` | 仅状态：降级/待复核 / 失败/阻断 |

**字体**：拉丁 `IBM Plex Sans`（界面）+ `IBM Plex Mono`（数字/ID/事件码）；中文系统栈 `"PingFang SC","HarmonyOS Sans SC","Noto Sans SC",sans-serif`。字阶 5 级：12/13/15/20/28 + 展示 34。正文中文 `line-height 1.75`，中文不做 tracking。

**布局**（保持现有 `360px + 主列`，但**去卡片化**）：

```text
┌ header ──────────────────────────────────────────────┐
│ ◈ DeepResearch   状态● 实时连接      [账号条]        │
├───────────────┬──────────────────────────────────────┤
│ 新研究        │ 研究 4f3a…   ●进行中    用时 02:13   │
│ [主题…]       │ ── 阶段阶梯 ─────────────────────────  │
│ 档位 ▸▸▸      │ 规划 ─ 检索 ─●─ 撰写 ─ 校验 ─ 渲染     │
│ [开始研究]    │ ══════════ 62% ══════════             │
│               │                                      │
│ ── 运行边界 ──│ 指标   节点 18 │ Token 42k │ 来源 26   │
│ ── 命中文件 ──│ ─────────────────────────────────────│
│  报告.pdf ×3  │ 活动流（规则线分隔，等宽时间码）      │
│               │ 02:11 ✓ 检索证据  3.2s  depth 4      │
│               │ ─────────────────────────────────────│
│               │ 报告（正文列 max 72ch）              │
│               │ ─ 引用清单：编号 + 严格/宽松 + 置信度 │
└───────────────┴──────────────────────────────────────┘
```

**签名元素**：**阶段阶梯**——5 段横排刻度，与实时进度条共用同一条基线；它同时是进度、是导航、是「系统在做什么」的自证。
**替换规则**：卡片 → 规则线分区（仅可交互弹层保留 surface）；全大写 eyebrow → 中文小标签 + 2px `signal-mint` 短线；按钮去掉 `→`，改「开始研究」直述；光晕/渐变全部移除（shimmer 仅保留为不确定态）。
**代价**：中等（token + 组件类改造为主，布局几乎不动）。**风险**：深色仪器风若执行粗糙会显得「终端简陋」，需要严格字阶与对齐纪律。
**为什么推荐**：与现有信息架构和数据流零冲突，一次 PR 可完成；直接消化审计里「4 色并用 / 卡片套件 / eyebrow」三条。

### 方向 B · 研究档案（Research Dossier）｜浅色 · 文档优先

**一句话**：这个产品的可信度来自**可核查的文本**——那就把界面做成一份档案：报告是主角，证据是页边批注。

**色彩令牌**

| 名称 | 值 | 用途 |
|---|---|---|
| `paper` | `#F4F6F3` | 页面底（中性冷纸色，刻意避开奶油色） |
| `sheet` | `#FFFFFF` | 报告纸面 |
| `rule` | `#D9DEDA` | 细线 / 表格线 |
| `ink` | `#171B19` | 正文 |
| `ink-muted` | `#5E6862` | 次要文字 |
| `stamp-blue` | `#1E5AD8` | 唯一强调：链接、当前步骤、主按钮 |
| `stamp-red` | `#B5432E` | 仅：阻断 / 已标记 / 待复核 |

**字体**：报告 `"Noto Serif SC","Source Han Serif SC",serif`（长文阅读）；界面 `"Noto Sans SC"`；数字 `IBM Plex Mono`。正文 17px / 1.9，行宽 ≤ 68ch。

**布局**：报告成为首屏主角，运行状态压缩为顶部横条，证据挂在**页边**：

```text
┌ header: ◈ DeepResearch   ●进行中 02:13  [账号]        ┐
├───────────────────────────────────────────────────────┤
│ 新研究 ▾（折叠抽屉：主题/档位/开始）                   │
├───────────────────────────────────┬───────────────────┤
│                                   │ 页边证据          │
│  报告（衬线、单列、68ch）          │ ① 严格通过 92%    │
│                                   │   rag:report.pdf  │
│  三、市场结构                     │ ② 宽松通过 71%    │
│  ……论述【1】……【2】                │   来源示例.org    │
│                                   │ ── 待复核 ──      │
│                                   │ ③ 未通过：越界引用 │
├───────────────────────────────────┴───────────────────┤
│ 状态带：阶段 │ 指标 │ 降级 │ 活动（横向滚动时间轴）     │
└───────────────────────────────────────────────────────┘
```

**签名元素**：**页边引用**——引用卡片与正文段落水平对齐，核查时视线不离开文本；无引用可核的段落以淡色下划线示警。
**替换规则**：删除卡片套件与所有渐变；用留白与细线分区；状态用「印章」式角标（文字 + 边线），不靠颜色。
**代价**：高（主题、版式、运行看板都要重排；浅色主题需重做全部对比度）。**风险**：浅色长时间盯屏对仪表场景不友好；「档案纸」气质若失手会滑向文艺模板（skill 点名的第一 cluster）。
**适用**：如果产品定位从「工作台」转向「审计交付物」。

### 方向 C · 信号台（Signal Bench）｜近黑 · 横向 · 工程实验室

**一句话**：把研究过程当**信号**看——事件流是示波带，报告在旁边并排阅读。

**色彩令牌**

| 名称 | 值 | 用途 |
|---|---|---|
| `bench-black` | `#0A0C0D` | 底 |
| `bench-panel` | `#12161A` | 面板 |
| `bench-grid` | `#1E252B` | 网格刻度 |
| `bench-ink` | `#E8ECEF` | 主文字 |
| `bench-muted` | `#93A0A8` | 次要文字 |
| `copper` | `#D98B4A` | 唯一强调（非绿、非紫，刻意避开 cluster） |
| `scope-blue` / `alert` | `#6FA8DC` / `#E06666` | 信号选中 / 阻断 |

**字体**：`Archivo`（标题）+ `JetBrains Mono`（全部数据与事件码）+ 中文 `"Noto Sans SC"`。字阶偏工程：11/12/14/18/24。

**布局**：顶部命令条 + 左右并列（过程 / 结论）：

```text
┌ 命令条：◈ DeepResearch │ 主题… │ 档位 │ [开始] │ 用时 │ ● │
├───────────────────────────────┬───────────────────────┤
│ 事件示波带                     │ 报告（可并排滚动）     │
│ 规划 ─■                        │ # 结论                │
│ 检索 ─■■■□□□ (depth 4/6)      │ ……【1】……             │
│ 撰写 ─▶                        │                       │
│ ── 降级：Bocha 429 ──          │ 引用 ① ② ③（侧栏切换） │
└───────────────────────────────┴───────────────────────┘
```

**签名元素**：**示波带**——节点以水平信号段呈现，depth 以刻度显示，替代「卡片列表」。与现有「不伪造进度」的诚实原则天然契合。
**替换规则**：彻底去卡片；事件流不再逐行列表，改为分段信号；copper 单色强调。
**代价**：高（新组件多，动效与可访问性成本高）。**风险**：新颖度与学习成本；信号带如果信息密度过高，移动端体验差。

## 3. 自我批判（首轮方案 → 修正）

| 首轮倾向 | 问题（skill 的「默认脸」检查） | 修正 |
|---|---|---|
| A 用「终端绿」 | 近黑+酸绿是 cluster #2 | 换成偏青的 `signal-mint #5FE3A1` 且**只用于进行态**，其余中性；状态色降饱和 |
| B 一开始想用奶油纸 + 衬线 + 陶土 | 命中 cluster #1（Anthropic 自己的默认脸） | 纸色改中性冷灰 `#F4F6F3`，陶土改档案蓝，衬线**只用于报告正文** |
| C 想用青色霓虹 | 与现状 cyan/emerald 同质 | 改铜色 `#D98B4A`；强调收敛到单色 |
| 三者都想保留的 | 「全大写 eyebrow + 中点串 + `→` 按钮」是模板 chrome | 全部移除：eyebrow 改中文小标签+短线；分隔用实线；按钮用动词直述 |

**逐项自检（是否「换个皮也成立」）**：A 的阶段阶梯、B 的页边引用、C 的示波带，都是**只属于这个产品**的结构性动作（进度诚实 / 引用核验 / 过程信号），不是通用装饰；三者任一套换到别的后台都会显得别扭——通过。

## 4. 对比与建议

| 维度 | A 任务控制台 | B 研究档案 | C 信号台 |
|---|---|---|---|
| 主题 | 深色 | 浅色 | 近黑 |
| 主强调 | signal-mint | stamp-blue | copper |
| 签名结构 | 阶段阶梯 | 页边引用 | 事件示波带 |
| 与现有布局冲突 | 低 | 中高 | 高 |
| 实施成本 | **中（1 个 PR）** | 高（2–3 个 PR） | 高（2–3 个 PR） |
| 长文阅读 | 好 | 最佳 | 一般 |
| 移动端 | 好 | 好 | 需额外适配 |
| 风险 | 执行纪律 | 滑向文艺模板 / 浅色疲劳 | 学习成本 |

**建议**：选 **A（任务控制台）**作为 R6b 落地——它直接吃掉审计指出的视觉问题（4 色并用、卡片套件、模板 eyebrow、渐变/玻璃），保留全部信息架构与 testid，成本可控；B/C 可以在内测数据与用户反馈后再评估（若产品叙事转「审计交付」，B 值得单独立项）。

## 5. 选定后的 R6b 施工清单（以 A 为例）

1. `tailwind.config.js`：写入 `console-*` 与 `signal-*` 令牌；删除未用 token；
2. `index.css`：`.surface-card` 系改为「panel + hairline」；移除渐变/光晕；聚焦环统一；
3. 组件类：eyebrow 改中文标签组件；按钮去 `→`；状态徽标降饱和；
4. 字阶：引入 `IBM Plex Sans/Mono`（自托管子集或系统回退，离线可用）；
5. 逐板块替换配色（launch / run / report / history / KB），e2e 全绿 + 对比度抽查（axe 手动跑一遍）；
6. 截图基线（R7）随新视觉建立。
