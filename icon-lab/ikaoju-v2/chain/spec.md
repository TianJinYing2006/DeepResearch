# 引签 · 报告内引用链（组件规范 v0.1）

> 一句话：报告正文里的 `[来源: N]` 不是一个角标，而是**一条链** ——
> 被引用的那一行、一跳一跳的虚线、骑在页缝上的签，同一种颜色，因为它们本来就是同一件事。

原型：`chain.html`（双击即可打开，无构建、无依赖）
验收：`verify.py`（无头断言 + 像素复核）、`shot.py`（真渲染截图 + 拼板 → `chain-sheet.png`）

---

## 0. 为什么是「组件」而不是「图标变体」

图标里那条链，在产品里**已经有对应的数据**，只是从来没被画出来：

- `[来源: N]` → `Citation.finding_id`（论断 → 工作证据）
- `Citation.evidence_id` / `content_hash` → 压缩前的**原文证据**（工作证据 → 原文）
- `Citation.snapshot_id` / `quote` / `quote_status` / `match_level` → **来源快照**里的逐字引文与定位级别

三段虚线不是修辞，它就是这三跳的图形化。所以「多源印证」也不需要单独的图标变体：
`Citation.independent_source_count` / `supporting_evidence_ids` 已经是产品字段，签叠签即可。

## 1. 字段 → 形色（一对一，不发明）

| 产品字段 / 口径 | 链上的形 | 备注 |
| --- | --- | --- |
| 该句 claim + `[来源: N]` 位置 | **同色下划线**（被引用的那一行） | 从上一个中文句读切到标记处 |
| `Citation.finding_id` | **第 1 段虚线** | 论断 → 工作证据（Finding N） |
| `Citation.evidence_id` + `content_hash` | **第 2 段虚线** | 工作证据 → 原文证据（压缩前） |
| `Citation.snapshot_id` + `quote` + `quote_status` + `match_level` | **第 3 段虚线** | 原文 → 来源快照（L0 精确 / L1 空白折叠 / L2 标点归一） |
| `independent_source_count` / `supporting_evidence_ids` | **叠签枚数**（最多 3 枚，其余记数） | 多源印证：多发一枚签，不新增颜色 |
| `verified` | 已核验 · 青蓝**实心** | 存在且忠实 |
| `verified_relaxed` | 待复核 · 浅蓝**实心** | 宽松口径通过 ≠ 严格通过 |
| `verification_failed`（UNKNOWN） | 待复核 · 浅蓝**空心** | 没结论：用**形**区分，不新增颜色 |
| 其余（确证失败） | 未通过 · 朱 | |
| `[来源: 信息不足]` | 无据 · 琥珀空心**虚线边** | 沿用产品既有 `claim-unsourced` 的点线色 |

「无据」不是第四种状态，而是**链没建起来**：写作层没有可用编号，缺口留在正文里，不补一个假来源。

---

## 2. 四态 → 三色：哪里不能抹平

后端与前端是**四态**（严格通过 / 宽松通过 / 确证失败 / 校验未完成，见 `lib/quality.ts::citationVerdict`），
签面只有**三色**。映射规则：

```
严格通过              → 已核验（青蓝实心）
宽松通过 / 校验未完成  → 待复核（浅蓝；后者空心）
确证失败              → 未通过（朱）
[来源: 信息不足]       → 无据（琥珀空心虚线边）
```

两条硬规则（写进组件、也写进自检）：

1. **UNKNOWN 不得显示为通过** —— 产品文档里最忌讳的假信号；
2. **签面用品牌三态，卡里必须写产品的精确口径**（存在性 / 严格 / 宽松 / 未完成）——
   三色是「站不站得住」的第一眼判断，精确口径不能被它抹平。

整条链一起变色：链色 = 该引用**最坏**的一条，严重度顺序与 `qualityVerdict` 同序
（`refuted > unknown > relaxed > verified`）。

## 3. 颜色：全部来自既有令牌

| 用途 | 取值 | 来源 |
| --- | --- | --- |
| 纸页 / 桌面 | `#FFFFFF` / `#F4F6F3` | `tailwind.config.js` `sheet` / `paper` |
| 墨底页缝 / 正文 | `#171B19` | `ink` |
| 分隔线 | `#D9DEDA` | `rule` |
| 已核验 | `#1E5AD8` | `stamp-blue` |
| 未通过 | `#B5432E` | `stamp-red` |
| 无据 | `#9A6B1F` | `stamp-amber`（`claim-unsourced` 同色） |
| 待复核 | `#6E8FD9` | `stamp-blue` 压深版（见下） |

两处**有意的**偏离，都因为组件比图标多了「白纸」这一侧：

1. **待复核**：图标里是 `#7C9BE0`（只出现在墨底上）。组件里签骑在白纸与墨底之间，
   `#7C9BE0` 对白纸只有 **2.76:1**。压深到 `#6E8FD9` ⇒ 纸侧 **3.18:1**、墨侧 **5.46:1**，两侧都过 3:1。
2. **签的 2px 纸色描边**：蓝对墨底只有 **2.91:1**。描边把签与墨底隔开（印刷上的「压印留白」），
   描边对墨底 **16.01:1**。自检里断言的是这条真正起作用的隔离线，而不是那个凑不够的比值。

## 4. 交互与动效

| 时机 | 行为 |
| --- | --- |
| 静置 | 链是**静的**：下划线 + 三段虚线 + 一枚（或数枚）签。长报告里 100 条引用也不会满屏动 |
| 悬停 / 聚焦 | 该链的虚线流动（marching ants，复用登录门的 `trace-flow` 语汇），其余链不动 |
| 点签 / 回车 | 出处卡从签上展开：claim 原文 + 三跳 + 出处 + 引文 + 精确口径 + 说明 |
| 卡内悬停某一跳 | 对应的那一段虚线加粗回指（跳 ↔ 虚线一一对应） |
| Esc / 点关闭 | 收起并把焦点还给签；`←` `→` 在链之间移动 |
| `prefers-reduced-motion` | 全部瞬时呈现；**终态不变**（动效只影响「怎么出现」，不影响「出现成什么样」） |

无障碍：签是 `<button>`，带 `aria-label`（含状态与下一步）、`aria-expanded`、`aria-controls`；
状态不只用颜色表达（卡里有文字口径，签有 `aria-label`）。窄屏（≤860px）页缝收掉，签落回行内，卡变底部抽屉。

## 5. 接入 `ReportView`（真正的落地）

现状：`ReportView` 只收 `report: string`，正文里的 `[来源: N]` 是纯文本。接入分三步：

1. **传 cites**：`<ReportView report={result.report} citations={result.citations} />`
   （四个调用点里只有报告类需要：`ReportPanels` / `HistoryPanel` / `SharedReportPage`；帮助与法务文档不传。）
2. **换标记**：在 `react-markdown` 的 `p` 组件里，把文本节点按 `/\[来源:\s*([^\]]+)\]/` 切开，
   前一段的**最后一句**（按 `。！？；` 断句，不要用 `.`，会切进 URL 与文件名）包成 claim，标记处留一个零宽锚点。
3. **建链**：编号 → `Citation`（`finding_id` 对齐），按 §2 求最坏态；`independent_source_count` → 叠签枚数。

⚠️ **已知坑（必须一起改）**：`ReportView` 现在的「无引用段落」判定是
`nodeText(children).includes('[来源:')`。标记被替换成链之后，子节点里不再有这串字符，
**所有**实质段落都会被判成无引用（整篇点线示警）。必须改成从**原始 markdown 段落**判。

其它约定：

- 多编号 `[来源: 5, 72, 77]`（Validator 会拆成多条独立引用）与渲染层标注过的
  `[来源: 5 · 🔵web]` 两种形态都要能吃 —— 解析时取每段里的首个整数；
- 导出（Markdown / PDF / DOCX）**不动**：链只在呈现层，产物里仍是 `[来源: N]` 文本，可审计性不被 UI 改写；
- 长报告分段渲染（`CHUNK_CHARS`）不影响：链只在段内闭合，不跨段。

## 6. 自检抓到的真缺陷（记一笔）

`verify.py` 断言「出现动效终态：路径与签全部可见」时挂了 —— 根因不是测试写错，是组件真错：
字体就绪（`document.fonts.ready`）与窗口 resize 都会重建 SVG 组，把 `is-in` 抹掉，
链会**整条凭空消失**。修法是让「已出现」成为链自身的状态（`chain.shown`），重排后补回。

这正是把设计约束写成断言的价值：这类缺陷肉眼要等到「改一下窗口大小」才会撞见。

---

## 7. 这一版没做（候选）

- 正文 → 页边签的**双向高亮**（现在只有卡 → 虚线一段）；选区/引用悬浮联动；
- 「未通过附录」的落点（`refuted` 在报告末尾的呈现）；
- **密度策略**：>100 条引用时是否只对「非通过态」默认出签，其余折叠成 1px 短横；
- 竖排界行版（编辑/印刷版式）——与组件不冲突，是另一张脸。

## 8. 复现

```powershell
# 截图 + 拼板（需要本机 Chrome；沙箱内 Chrome 起不来）
python icon-lab/ikaoju-v2/chain/shot.py

# 无头断言（4 种配置）+ 像素复核
python icon-lab/ikaoju-v2/chain/verify.py
```

`chain.html` 支持的调试开关：`?view=states`（五态对照页）、`?open=2`（展开第 2 条链）、
`?motion=0`（跳过出现动效）、`?shot=1`（隐藏实验室横条，便于裁切）、`?assert=1`（把自检结果写进标题与页面）。
